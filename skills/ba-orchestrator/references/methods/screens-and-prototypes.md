# Screens and Prototypes

`T5 Requirements Specification › 5.3 User Interface`

## Problem Solved

Eliminates ambiguity in complex user interface designs and ensures high usability prior to programming.

## BA Lifecycle Phase

specification

## Input Artifacts

Task descriptions, Virtual Windows, screen sketches, user profiles.

## Output Artifacts

Screen mockups/prototypes, process descriptions for buttons/menus, error message lists.

## Participants & Roles

BA, UI designer, developer, tester, end user.

## Prerequisites

Detailed task analysis and clear understanding of workflow sequences.

## Step-by-Step Procedure

Draft screen layouts based on task data requirements.
2. Define logic/pseudo-code for interactive controls (buttons, menus).
3. Define error messages and validation checks.
4. Conduct usability testing on the prototype using realistic tasks.
5. Iterate prototype based on observed user failures.
6. Freeze prototype as a design-level requirement.

## Analyst Questions & Prompts

What should happen when this button is clicked? What error message should be displayed if this input is invalid?

## Minimal Realistic Example

R1: The product shall use screen pictures in Appendix XX; Check-in button executes pseudo-code logic in Appendix YY.

## Quality Criteria & Verification

Usability testing with target end users, direct visual verification against prototype during delivery testing.

## Errors & Anti-Patterns

Specifying prototypes as rigid requirements without prior usability testing; using fixed screen prototypes for COTS acquisitions.

## When NOT to Use

COTS acquisition projects, or early elicitation phases where project scope is volatile.

## Alternatives & Complementary Methods

Task Descriptions, Virtual Windows, Tasks & Support.

## Supported Decisions

UI design freezing, front-end software architecture, delivery acceptance criteria.

## AI & Agentic Adaptation

Generate runnable HTML/CSS prototypes directly from textual pseudo-code and task inputs using LLMs.
