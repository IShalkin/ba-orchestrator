# Tabular Requirement Representation

`T5 Requirements Specification › 5.4 Business Rules and Decision Logic`

## Problem Solved

Eliminates redundant, monotonous, or prone-to-omission text lists generated by multi-variable permutations of functional requirements.

## BA Lifecycle Phase

specification

## Input Artifacts

Grid/matrix of input factors, jurisdictions, document formats, or state-condition pairs

## Output Artifacts

Requirement tables with systematic ID extensions/suffixes

## Participants & Roles

BA, developers, testers

## Prerequisites

Identification of orthogonal variables (e.g., combinations of formats and jurisdictions) that dictate system functionality.

## Step-by-Step Procedure

Identify the recurring requirement pattern across multiple variable combinations.
2. Write a single parent requirement referencing a structured matrix.
3. Create a table listing independent variables as rows and columns.
4. Populate table cells with unique identifier suffixes or status codes (or N/A for invalid combinations).
5. Verify that every cell contains explicit entries so no combinations are omitted unintentionally.

## Analyst Questions & Prompts

Are there multiple variable dimensions driving identical capability forms? Are any variable combinations logically invalid or not applicable?

## Minimal Realistic Example

Table 11-1 maps Jurisdictions (Federal, State, International) vs Formats (Tagged, Untagged, ASCII), where cell entry '1' expands to 'Editor.DocFormat.1: The Text Editor shall be able to parse Tagged documents that define Federal laws.'

## Quality Criteria & Verification

Ensure every matrix cell is populated (or explicitly marked N/A); verify unique labeling for all permutations; verify completeness against domain rules.

## Errors & Anti-Patterns

Leaving cells blank instead of explicitly writing N/A; omitting possible permutations in long narrative lists.

## When NOT to Use

When system actions across different scenarios do not follow a uniform, repetitive structural pattern.

## Alternatives & Complementary Methods

Decision tables, decision trees, textual requirement lists.

## Supported Decisions

Acceptance, compliance.
