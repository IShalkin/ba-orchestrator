# User Analysis (User Classes)

`T3 Stakeholders › 3.1 Stakeholder Identification`

**Also described as:** User analysis

## Problem Solved

Identifies and classifies user populations into user classes, analyzing their characteristics, demographics, tasks, and working environments to guide UI/UX and work practice design.

## BA Lifecycle Phase

Define Requirements / Elicitation

## Input Artifacts

Stakeholder list, process maps, user profiles, market analytics.

## Output Artifacts

User Classification Document detailing user classes, attributes (type, experience, frequency, motivation, numbers, training, tasks), and usability considerations.

## Participants & Roles

BA, Usability/UX Specialists, Business Users, System Actors.

## Prerequisites

Identification of user groups interacting with proposed systems/processes.

## Step-by-Step Procedure

Identify user populations interacting with system (direct, intermediaries, customers).
2. Group users into similar User Classes.
3. Analyze attributes for each class (Tech literacy, expectations, motivation - mandatory/discretionary, population size, training, tasks, environment).
4. Document usability considerations.
5. Input findings into UI/UX design and requirements catalog.

## Analyst Questions & Prompts

Who will use this system? Is usage mandatory or discretionary? How tech-literate are they? What environment do they work in? What tasks do they perform daily?

## Minimal Realistic Example

Documenting User Class 'Hotel Reception Desk Staff': High frequency (80/day), mandatory usage, high time-pressure with waiting clients, driving UI requirements for fast-access keys and high system responsiveness.

## Quality Criteria & Verification

Usability decisions backed by objective user attributes rather than developer assumptions; complete coverage of all user classes.

## Errors & Anti-Patterns

Assuming all users possess high tech-literacy; ignoring discretionary users who can easily abandon a site; designing interfaces based on developer preferences.

## When NOT to Use

For purely automated back-end batch interface systems with zero human interaction.

## Alternatives & Complementary Methods

Personas, Scenarios, Wireframes, Prototyping.

## Supported Decisions

UI/UX design architecture, training program design, non-functional usability requirement specification, job role design.

## AI & Agentic Adaptation

User analytics AI processes real-time user session logs to automatically cluster users into attribute classes and generate candidate usability profiles.
